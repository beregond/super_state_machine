# AGENTS.md

## Overview
`super_state_machine` is a small Python (>=3.11) library for state machines built on `enum.Enum`. Stack: hatchling + versioningit build, pytest, ruff, Sphinx docs. `machines.py` holds `StateMachine` / `PropertyMachine`, `utils.py` holds the state-change helpers (`set_`, `force_set`, translators), and `extras.py` holds `set_`-based descriptors.

## Layout
- `src/super_state_machine/` — package: `machines.py`, `utils.py`, `extras.py`, `errors.py`, `__init__.py` (NullHandler for logging), `_version.py` (generated by versioningit, do not edit).
- `src/tests/` — plain pytest functions (`test_machines.py`, `test_transitions.py`, `test_utils.py`, `test_extras.py`, `test_logging.py`).
- `docs/` — Sphinx with the Furo theme (modelled on `../jsonmodels`). `docs/readme.rst` does `mdinclude` of `README.md`, so README sections appear in the docs automatically. Guide pages: `usage`, `transitions`, `options`, `property_machine`, `logging`, `errors`, `cookbook`; `contributing`/`authors` have their own content (there are no root `CONTRIBUTING.rst`/`AUTHORS.rst`). `autosectionlabel` is on with document prefixes (`:ref:\`usage:forced set\``). Read the Docs installs the package (`conf.py` reads the version from metadata).
- Doc examples are doctests that match the current API (exact values only, initial state required, `transitions` maps source -> targets). Verify: `PYTHONPATH=src python -m pytest -q --doctest-glob="*.rst" --doctest-glob="README.md" docs README.md` (6 passed). Build: `uv run --extra docs sphinx-build -W -b html docs docs/_build/html`.
- `README.md` — user docs.
- `HISTORY.rst` — changelog, **never edit it directly**. It is generated by [pyhistory](https://pypi.org/project/pyhistory/) from the one-line entries in `history/` at release time.
- `history/` — pending changelog entries, one file per entry, created by `pyhistory add`. Commit these files.
- `.github/workflows/test.yml` — CI: pytest with `--cov` on Python 3.11–3.15, and a lint job running `astral-sh/ruff-action@v4.1.0` twice (exact tag: ruff-action v4+ publishes no floating `v4` major tag, so `@v4` fails to resolve) (`check`, then `format --check --diff`). The action takes the ruff version from the `ruff==` pin in `pyproject.toml`'s `dev` extra. Without that pin it installs the latest ruff, which once broke CI with about 60 new default-rule errors.

## Conventions
- Tests: plain pytest functions in `src/tests/`; use `caplog` / `capsys` for logging.
- Public API and signatures stay stable (e.g. `force_set(self, state)`).
- Both `.format` and `%s` styles exist in the code. Logging uses lazy `%s` arguments.
- Ruff check and format must be clean under the pinned version (`ruff==0.17.6` in `pyproject.toml`). Config is in `[tool.ruff]`: `target-version = "py311"`, and `RUF012` is ignored in `src/tests/**` because `class Meta:` is declarative config, not mutable defaults.
- To bump ruff, change the pin in `pyproject.toml` only (CI follows it). Then run check and format with the new version and fix what it reports.
- Intentional rule violations get an inline `# noqa: <RULE> - <reason>` (e.g. `TRY004` in `machines.py`, where the public API raises `ValueError`; `PIE796` in tests that check duplicate enum values).
- Changelog: for every user-visible change, run `pyhistory add "<one-line message>"` from the repo root. It writes a new file in `history/`. Do not touch `HISTORY.rst`: `pyhistory update <version>` merges `history/` into it during a release, and that is the maintainer's job.
- Never add `Co-Authored-By` or any other AI attribution trailer to commit messages (user's global rule; it overrides default attribution guidance). Do not commit unless asked.

## Commands
- Tests: `python -m pytest -q src` (baseline: 63 passed).
- Ad-hoc scripts: `PYTHONPATH=src python script.py` (the package is not installed in the default Python).
- Lint (same version as CI): `uvx ruff@0.17.6 check .` and `uvx ruff@0.17.6 format --check .`. Do not use pyenv `ssm`'s ruff: it is 0.12.12, which passes code that CI rejects.
- History entry: `PYENV_VERSION=pyhi2 pyhistory add "Added X."`. Preview pending entries with `pyhistory list`.

## Features
### Logging
- Module-level `logger = logging.getLogger(__name__)` in `src/super_state_machine/utils.py` (name `super_state_machine.utils`). `src/super_state_machine/__init__.py` adds a `NullHandler` to the `super_state_machine` logger, so the library is silent by default. Users enable it via `logging.basicConfig(level=logging.DEBUG)` or by adding handlers to `super_state_machine`.
- `utils.force_set` does the translation, the `setattr` and the logging. `set_` calls `self.force_set(state)` after the `can_be_` check, exactly as on master; keep that call path for backward compatibility (a patched `force_set` must still be hit by `set_`, see `test_set_goes_through_patched_force_set`). `state = ...` and the generated `set_<state>` methods go through `set_`.
- One DEBUG record per successful change: `"%s (id=%s): %s -> %s"`, giving e.g. `Task (id=140...): draft -> scheduled`. The old state is None-safe. There is no "(forced)" marker: `force_set` can't tell direct calls from `set_` calls without changing its signature.
- `force_set` can't be overridden in the class body or a base class: the metaclass raises "Name collision" (`hasattr` check in `_add_new_methods`). Subclassing a built machine also fails. Only post-creation patching works.
- Rejected transitions are not logged (optional, not implemented).
- Design decision: the maintainer rejected PR #2 (`LoggingPropertyMachine` subclass, per-instance loggers named by instance, `logging_name`). The accepted approach follows the stdlib "configuring logging for a library" howto: one logger per module, no subclass, no per-instance loggers, no public API changes. To tell classes or instances apart, put the class name and id in the message, not in the logger name. `machines.py` is untouched by the logging feature.

## Gotchas
- `_version.py` is generated; do not edit.
- Local ruff installs (e.g. pyenv `ssm`, 0.12.12) may differ from the CI pin. Always lint with `uvx ruff@<pinned version>`.
- pyhistory is not a declared dependency. `.venv/bin/pyhistory` is a broken shim (ModuleNotFoundError), and pyenv `pyhi` fails on a missing `toml`. `PYENV_VERSION=pyhi2` (or `pyhi3`) works.
- The package is not installed in the default Python; use `PYTHONPATH=src` for ad-hoc runs. `python -m pytest -q src` works as is.
- Test count baselines: 55 before logging, 61 with logging, 63 after the ruff 0.17 cleanup (adds the `get_config` and patched-`force_set` tests). Earlier plans quoting 70 were wrong.
- QA verified silent-by-default and `basicConfig(level=DEBUG)` output with a throwaway script run under `PYTHONPATH=src`. The automated tests cover the record format only through `caplog`.
